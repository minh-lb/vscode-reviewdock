**Status:** ID-level planning baseline. Planned does not mean implemented or verified.

## Rules

- Every unique requirement/decision ID extracted from SRS is listed below; this mapping must be updated when SRS changes.
- Design owner is the primary boundary. Milestones are plans, not completion evidence.
- Test-family references must resolve to concrete test names/manual cases before milestone acceptance.
- Status: Planned, In progress, Implemented, Verified, Deferred, Blocked. Only Verified means evidence exists.
- Decision IDs (DEC-*) trace to approval/evidence rather than runtime tests.

## Verification evidence

Move to Implemented only after code exists and review is complete. Move to Verified only after named tests pass or manual records capture environment, steps and result; provider mutations are checked against test instances; security, cancellation, stale-data and error paths pass; and no P0/P1 defect blocks acceptance.

## Maintenance gate

CI should compare IDs extracted from SRS against this table and fail on missing/duplicate IDs. Until that validator exists, reviewers must compare manually. Replace family references with concrete test IDs as tests become concrete. The matrix records planned traceability, not proof of implementation.
